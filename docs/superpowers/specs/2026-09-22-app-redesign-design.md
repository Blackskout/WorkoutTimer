# Редизайн приложения — дизайн

**Дата:** 2026-09-22
**Ветка:** `feat/redesign`

## Проблема

Приложением пользуются в зале почти каждый день, и оно выглядит как шаблон Android Studio, которым и является: фиолетовая палитра `Purple40/Purple80` из `Color.kt`, `Typography` с одним переопределённым стилем в `Type.kt`, dynamic color, красящий интерфейс в цвет обоев. Визуальный язык не сложился — карточки списка обведены рамкой, карточки редактора подняты тенью, кнопки везде дефолтные, отступы подобраны на глаз (`8.dp` у одной карточки, `24.dp` у поиска, `16.dp` у остальных).

Функционально мешает другое:

- **Список не показывает, что делать дальше.** Тренировки идут в порядке, который задаёт `ORDER BY orderInWorkout DESC` в `WorkoutDao.kt:48` для поиска и полное отсутствие `ORDER BY` в `getAllWorkouts()` (`WorkoutDao.kt:19`). Пользователь держит ротацию в голове и вычисляет следующую тренировку глазами по датам.
- **Экран выполнения тратит место на мёртвые элементы.** `SystemMediaControllerCompat` (`SystemMediaController.kt:30`) рисует prev/play-pause/next размером 90dp каждая. Кнопки шлют `KeyEvent` через `AudioManager`, срабатывают с задержкой, а иконка play/pause статична — состояние плеера приложению неизвестно, `Icons.Default.PlayArrow` захардкожена на `:105`. Пользователь перестал ими пользоваться именно поэтому: потребность в управлении музыкой на отдыхе осталась, её не закрывает текущая реализация.
- **Редактор упражнения — пять текстовых полей в одной строке.** `CreateWorkoutScreen.kt:270–330`: поля шириной 68–100dp с числовой клавиатурой, отдых только в целых минутах (`:322`, `minutes.coerceAtLeast(1) * 60`). Порядок упражнений менять нельзя.
- **Завершение тренировки показывается `AlertDialog`'ом** (`WorkoutExecutionScreen.kt:265`) — главный момент тренировки выглядит как системное уведомление.

## Цель

Единый визуальный язык «Dark Athletic» — тёмный фон, один лаймовый акцент, крупная типографика, читаемая на вытянутой руке, — и перестройка экранов вокруг того, как приложением реально пользуются: главный экран отвечает на вопрос «что делать сегодня», экран выполнения отдаёт максимум места текущему подходу.

Визуальное направление, акцентный цвет и компоновку каждого экрана выбрал пользователь; макеты лежат в `.superpowers/brainstorm/40066-1790064499/content/`.

## Вне рамок

Отдельные фичи, каждая со своей спекой, в этом порядке:

- **Правка веса и повторов во время тренировки.** Тап по плитке на экране выполнения открывает барабаны и пишет значение в тренировку. Сюда же — единица измерения упражнения: на части тренажёров (кроссовер) нагрузка задаётся номером плиты, а не килограммами, и `Exercise.weight: Double` с подписью «кг» для них врёт. Эта спека готовит для неё `StatTile` и `WheelPicker`: плитки уже стоят на своих местах и не реагируют на тап, барабан уже написан для редактора.
- **Настройки.** Звук, вибрация, поведение экрана, выбор темы (включая светлую), переезд экспорта/импорта. До этой спеки иконки настроек в шапке нет.
- **Статистика и прогресс.** Графики веса и длительности по сессиям, серии, итоги недели. До неё история остаётся списком сессий.
- **Светлая тема.** Появится вместе с настройками. До тех пор приложение всегда тёмное.
- **Управление музыкой на отдыхе.** Рабочая замена сломанным кнопкам: `MediaController` поверх `MediaSessionManager` даёт настоящее состояние воспроизведения, название трека и команды без задержки. Открытый вопрос — где это живёт на экране: кольцо таймера уже занимает центр, и мини-плеер не должен его теснить. Решается после того, как новый экран отдыха поживёт в зале и станет видно, сколько места реально свободно.

## Решения по продукту

### Очередь ротации

У пользователя шесть тренировок, идущих по кругу: понедельник(1), среда(1), пятница(1), понедельник(2), среда(2), пятница(2). Следующая — та, которую не делали дольше всех. Это ровно `lastUseAt ASC`, и приложение уже хранит нужные данные — просто не использует их для порядка.

Круг ломается, когда тренировка пропущена: после болезни «самой старой» остаётся пропущенная пятница(1), хотя по дням недели идти надо на понедельник(2). Поэтому в меню карточки появляется **«Пропустить»**: тренировка помечается как сделанная сегодня и уезжает в конец очереди, но сессия в историю **не пишется** — статистика не должна считать пропуск тренировкой. Действие отменяемо через снекбар.

Это единственная новая продуктовая логика в спеке. Без неё главный экран, построенный на очереди, рассыпается на первой же пропущенной неделе.

### Виджет

`GetWidgetWorkoutsUseCase.kt:20` сортирует `sortedByDescending { lastUseAt }`, то есть первой в виджете стоит тренировка, которую только что сделали. Для быстрого старта нужна обратная: первой — следующая по очереди. Порядок меняется на возрастающий, раскладка виджета остаётся прежней, цвета переводятся на новую палитру.

## Часть 1: Дизайн-система

Новый пакет `presentation/ui/` — единственный источник цвета, типографики, форм и повторяющихся компонентов. Ни один экран после редизайна не задаёт цвет литералом и не подбирает отступ на глаз.

### Цвета

`Color.kt` переписывается целиком, `Purple40/80`, `PurpleGrey40/80`, `Pink40/80` удаляются.

| Токен | Значение | Где |
|---|---|---|
| `Background` | `#0B0B0F` | фон всех экранов |
| `Surface` | `#16161C` | карточки, плитки, поля |
| `SurfaceElevated` | `#1E1E26` | нижние листы, диалоги |
| `Outline` | `#26262E` | обводки карточек и плиток |
| `TextPrimary` | `#F2F2F5` | основной текст |
| `TextSecondary` | `#8A8A96` | подписи, метаданные |
| `TextMuted` | `#55555F` | шевроны, ручки перетаскивания |
| `Accent` | `#C6FF3D` | кольцо таймера, главная кнопка, прогресс |
| `OnAccent` | `#0B0B0F` | текст на акценте |
| `Destructive` | `#FF5C5C` | удаление, ошибки |

`Theme.kt`: `dynamicColor` и `LightColorScheme` удаляются, остаётся одна `darkColorScheme()`, в которую токены раскладываются по ролям Material 3 (`primary` = `Accent`, `onPrimary` = `OnAccent`, `background`, `surface`, `surfaceVariant` = `SurfaceElevated`, `outline`, `onSurface` = `TextPrimary`, `onSurfaceVariant` = `TextSecondary`, `error` = `Destructive`). Роли заполняются полностью, чтобы `AlertDialog`, `Snackbar`, `ModalBottomSheet` и текстовые поля красились сами, без переопределений на местах вызова.

`themes.xml`: `Theme.WorkoutTimer` переводится с `android:Theme.Material.Light.NoActionBar` на `Theme.Material.NoActionBar` с `windowBackground` = `#0B0B0F`, чтобы между сплешем и первым кадром Compose не мелькал белый фон. `colors.xml`: `splash_screen` — на `#0B0B0F`.

### Типографика

`Type.kt` заполняется целиком. Семейство — системное `FontFamily.SansSerif`, сторонние шрифты не подключаются.

| Стиль | Размер / вес | Назначение |
|---|---|---|
| `displayLarge` | 64sp / 800, tabular | таймер отдыха, итоговое время |
| `headlineMedium` | 26sp / 800, tracking −0.02em | название упражнения, заголовок экрана |
| `titleMedium` | 16sp / 700 | имя тренировки в карточке |
| `bodyMedium` | 14sp / 400 | основной текст, заметки |
| `labelSmall` | 11sp / 700, tracking 0.14em, uppercase | «eyebrow»-подписи («ПОДХОД 3 ИЗ 4», «СЛЕДУЮЩАЯ») |

Все стили, показывающие числа, получают `TextStyle(fontFeatureSettings = "tnum")` — без табличных цифр таймер дёргается на каждой смене разряда.

### Формы и метрики

`Shapes`: 12dp мелкие элементы, 16dp карточки/кнопки/плитки, 26dp верхние углы листов. Горизонтальный отступ экрана — 18dp везде. Вертикальный шаг между карточками — 8dp, между секциями — 18dp. Высота главной кнопки — 58dp.

### Компоненты

`presentation/ui/components/`, каждый с `@Preview`:

- `PrimaryButton` — лаймовая, 58dp, uppercase-текст 800.
- `SecondaryButton` — прозрачная с обводкой `Outline`.
- `StatTile` — крупное число + единица под ним. Принимает необязательный `onClick`; в этой спеке всегда `null` (задел под правку на ходу).
- `WheelPicker` — вертикальный барабан со снапом. Параметры: список значений, выбранный индекс, форматтер, подпись единицы. Ключевой компонент: используется в редакторе сейчас и в правке на ходу потом.
- `WheelRow` — несколько `WheelPicker` в ряд с общей полосой выделения.
- `AppBottomSheet` — обёртка над `ModalBottomSheet` с ручкой и цветами `SurfaceElevated`.
- `ActionSheet` — список действий с иконками, поддерживает деструктивный пункт.
- `ProgressSegments` — полоски по числу упражнений: выполненные, текущая, будущие.
- `RestRing` — кольцо таймера с временем в центре и подписью «из M:SS».
- `EyebrowLabel`, `SectionHeader`.
- `EmptyState` — иконка, текст, необязательная кнопка. Для пустого списка, пустой истории, ошибки загрузки.

Подтверждения (выход из тренировки, удаление, завершение последнего подхода) остаются `AlertDialog` — через тему они выглядят как часть приложения.

## Часть 2: Главный экран

`ListWorkoutScreen.kt` переписывается.

**Шапка.** «Тренировки» стилем `headlineMedium`, справа иконки поиска и экспорта/импорта. Поиск по тапу раскрывает поле над списком; пока поле активно, герой-карта скрыта и показывается плоский список совпадений.

**Герой-карта «Следующая».** Первая тренировка очереди: лаймовый градиент, лейбл «СЛЕДУЮЩАЯ», имя `headlineMedium`, метаданные «N упр · прошлый раз MM:SS · N дн. назад», тёмная кнопка «НАЧАТЬ», иконка ⋮ в углу.

**Очередь.** Секция «Дальше по очереди», карточки с номером позиции, именем, «N упр · MM:SS», давностью и ⋮. Тап — начать тренировку, ⋮ или долгий тап — `ActionSheet`: Начать / Пропустить / Редактировать / История / Удалить.

Приглушение «заброшенных» карточек (`isStaleWorkout`, `DateFormatter.kt:34`) удаляется вместе с функцией: в очереди давность видна из позиции.

**Счётчик упражнений.** `ListWorkoutState.workouts` — это `List<WorkoutEntity>`, в котором упражнений нет. Экран переводится на `GetAllWorkoutsWithExerciseUseCase`, уже существующий и уже используемый виджетом; `ListWorkoutState` начинает хранить `List<WorkoutWithExercises>`. `SearchWorkoutsUseCase` возвращает `List<WorkoutEntity>`, поэтому в режиме поиска карточки рисуются без счётчика упражнений — добавлять ещё один запрос ради этого не стоит.

**Пустое состояние.** `EmptyState` с текстом «Нет тренировок» и кнопкой «Создать тренировку».

## Часть 3: Экран выполнения

`WorkoutExecutionScreen.kt` переписывается. `WorkoutExecutionViewModel` не меняется: все состояния, таймеры, сохранение сессии остаются как есть.

**Шапка.** Стрелка «назад» и чип «Имя упражнения · 2/6 ▾». Чип открывает лист со списком упражнений: выполненные приглушены, текущее подсвечено, тап переходит через существующий `moveToSelectedExercise()`. `ExposedDropdownMenuBox` (`:287`) удаляется. Под шапкой — `ProgressSegments`.

**Active.** Eyebrow «ПОДХОД 3 ИЗ 4», название `headlineMedium`, две `StatTile` (вес, повторы), блок заметки с иконкой ✎, открывающей существующий `NoteEditDialog`. Внизу — ряд: компактная кнопка запуска Яндекс Музыки слева, `PrimaryButton` «ЗАКОНЧИТЬ ПОДХОД» на оставшуюся ширину.

**Rest.** То же, но вместо плиток — `RestRing`, eyebrow «ОТДЫХ · ДАЛЕЕ ПОДХОД N», кнопка «ПРОПУСТИТЬ ОТДЫХ».

**Finished.** Вместо `AlertDialog` (`:265`) — полноэкранное состояние: eyebrow «ГОТОВО», длительность стилем `displayLarge`, имя тренировки, `PrimaryButton` «НА ГЛАВНУЮ», вызывающая тот же `onExerciseCompleted`.

**Loading / Error.** Через `EmptyState`; `LoadingState` и `ErrorState` (`:325`, `:344`) удаляются.

**Медиа.** `SystemMediaControllerCompat` (`SystemMediaController.kt:30`) сокращается до одной кнопки запуска Яндекс Музыки — логика поиска приложения и отката в Google Play (`:44–70`) сохраняется без изменений.

Кнопки prev / play-pause / next и функция `sendMediaKeyEvent()` (`:126`) удаляются. Они шлют `KeyEvent` через `AudioManager.dispatchMediaKeyEvent()` — одностороннюю отправку без обратной связи, откуда и задержка, и статичная иконка: состояние плеера приложению неизвестно, `Icons.Default.PlayArrow` прошита на `:105`.

Вместе с ними удаляется `MediaButtonManager.kt` — класс нигде не используется и дублирует ту же отправку через `AudioManager`. Зависимость `androidx.media` не импортируется ни в одном файле и убирается из `build.gradle.kts` и `libs.versions.toml`.

Настоящая замена — `MediaController` поверх `MediaSessionManager`: двусторонняя связь с сессией плеера, реальный `PlaybackState` и метаданные трека. Требует разрешения «Доступ к уведомлениям» (`BIND_NOTIFICATION_LISTENER_SERVICE`) и пустого `NotificationListenerService` в манифесте, которое пользователь включает вручную в системных настройках.

В эту спеку она не входит, но не потому, что не нужна — см. «Управление музыкой» в разделе «Вне рамок». Кнопка запуска Яндекс Музыки остаётся единственным медиа-элементом до тех пор.

## Часть 4: Редактор тренировки

`CreateWorkoutScreen.kt` переписывается, `CreateWorkoutViewModel` получает одну новую команду.

**Список.** Поле «Название тренировки», секция «Упражнения · N», строки со сводкой «80 кг · 4×8 · отдых 2:30» и ручкой ≡. FAB «+» создаёт упражнение и сразу открывает лист редактирования.

**Перетаскивание.** Через `sh.calvin.reorderable:reorderable` — небольшая библиотека без транзитивных зависимостей, добавляется в `libs.versions.toml`. Перетаскивание берётся только за ручку ≡, чтобы не конфликтовать с прокруткой. По отпускании — `CreateWorkoutCommand.MoveExercise(from, to)`: список переставляется, `order` каждого элемента переписывается по новой позиции. Порядок уходит в БД только при сохранении (✓ в шапке) вместе с остальной правкой — как и все прочие изменения редактора.

**Лист редактирования.** Имя (единственное место с клавиатурой), `WheelRow` из четырёх барабанов, заметка, «Готово», «Удалить упражнение»:

| Барабан | Диапазон | Шаг |
|---|---|---|
| Вес | 0–300 | 2.5 |
| Подходы | 1–10 | 1 |
| Повторы | 1–50 | 1 |
| Отдых | 0:30–10:00 | 0:15 |

Отдых сейчас правится в целых минутах (`:322`), а хранится в секундах (`ExerciseEntity.restTimeMillis`), так что шаг 15 секунд ничего не ломает и не требует миграции.

Если у существующего упражнения значение не попадает в шаг барабана (например, вес 47.5 при шаге 2.5 попадает, а 47.3 — нет), барабан встаёт на ближайшее доступное. Такие значения могли попасть в базу только через импорт JSON.

## Часть 5: История и экспорт/импорт

**История** (`WorkoutHistoryScreen.kt`): строки с `HorizontalDivider` заменяются карточками — дата `titleMedium`, длительность лаймом. Пустое состояние через `EmptyState`.

**Экспорт/импорт** (`ExportImportScreen.kt`): две кнопки и абзац текста внизу заменяются двумя карточками-действиями с иконкой, заголовком и пояснением внутри карточки. В шапке появляется стрелка «назад» — сейчас её нет (`:95`), хотя экран открывается из списка и `onNavigateBack` в него уже передаётся.

## Часть 6: Изменения вне UI

Всё, что меняется за пределами `presentation/`:

1. **`WorkoutDao.getAllWorkouts()` и `getAllWorkoutsWithExercises()`** получают `ORDER BY lastUseAt ASC`.
2. **Поисковый запрос** (`WorkoutDao.kt:48`): `ORDER BY orderInWorkout DESC` → `ORDER BY workouts.lastUseAt ASC`. Текущая сортировка по полю упражнения в запросе, возвращающем тренировки, выглядит как недосмотр и в новой модели не имеет смысла.
3. **`GetWidgetWorkoutsUseCase.kt:20`**: `sortedByDescending` → `sortedBy`.
4. **`WorkoutRepository.updateLastUseAt(workoutId)`** дополняется перегрузкой `setLastUseAt(workoutId, timestamp)` — нужна, чтобы «Отменить» вернула прежнее значение. Существующий метод остаётся точкой входа для завершения тренировки.
5. **`SkipWorkoutUseCase(workoutId): Long`** — читает текущий `lastUseAt` через `getWorkoutById`, ставит `System.currentTimeMillis()`, возвращает прежнее значение для отмены. Сессию не создаёт. Обновление виджета срабатывает само: `WorkoutRepositoryImpl.updateLastUseAt()` уже дёргает `widgetUpdater.requestUpdate()` (`:101`).
6. **`UndoSkipWorkoutUseCase(workoutId, previousLastUseAt)`** — возврат прежнего значения через `setLastUseAt`.
7. **`CreateWorkoutCommand.MoveExercise(from, to)`** в `CreateWorkoutViewModel`.
8. **`libs.versions.toml`**: добавляется `reorderable`.

## Тестирование

Новые unit-тесты (`mockk` + `kotlinx-coroutines-test`, как в существующих):

- `SkipWorkoutUseCase`: ставит текущее время; возвращает прежний `lastUseAt`; не вызывает `addWorkoutSession`.
- `UndoSkipWorkoutUseCase`: восстанавливает переданное значение.
- `GetWidgetWorkoutsUseCase`: список отсортирован по возрастанию `lastUseAt` — существующий тест на убывание переписывается.
- `CreateWorkoutViewModel.MoveExercise`: перестановка вверх и вниз даёт ожидаемый список и непрерывные `order` от 1 до N.

Compose-превью для каждого компонента и для каждого состояния экрана (очередь, пустой список, поиск; Active, Rest, Finished, Error; редактор со списком и с открытым листом). Превью — основной способ проверять вёрстку без сборки на устройство.

Инструментальные UI-тесты не пишутся: в проекте их нет, а настройка Hilt-окружения для них по объёму сравнима с самим редизайном.

Существующие тесты правятся в трёх местах, остальные (`WorkoutExecutionViewModel`, `WorkoutHistoryViewModel`, маперы, `ScreenDeepLinkTest`, `WidgetSubtitleFormatterTest`) должны продолжать проходить без изменений:

- `GetWidgetWorkoutsUseCaseTest` — ожидание порядка переворачивается.
- `DateFormatterTest:77–95` — три теста `isStaleWorkout` удаляются вместе с функцией.
- `ListWorkoutViewModelTest:37` — `state.workouts` становится `List<WorkoutWithExercises>`, мок переключается с `GetAllWorkoutsUseCase` на `GetAllWorkoutsWithExerciseUseCase`. Добавляются тесты на «Пропустить» и отмену на уровне ViewModel.
