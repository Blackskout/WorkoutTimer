# Аудит интерфейса (impeccable), 01.10.2026

Источник: технический аудит (audit.native) и дизайн-разбор (critique) скилла
[impeccable](https://github.com/pbakaus/impeccable). Оценки: техника 13/20, дизайн 27/40 —
обе «приемлемо».

Каждое замечание перепроверено по коду master (a5e8994) и на эмуляторе Pixel 8 Pro,
включая системный шрифт 200%. Ниже — только то, что подтвердилось; отброшенное — в конце.

Порядок работ — от простого и необходимого к сложному. Каждая порция — отдельный PR со своим
согласованием дизайна (superpowers: brainstorming → «да» → реализация).

## PR 1 — явные баги

- [x] **Двойное нажатие на главную кнопку.** «Закончить подход» на том же месте становится
  «Пропустить отдых»; защиты от второго касания нет. Проверено: два быстрых касания —
  «подход 3 → подход 4», отдых пропущен. То же при касании, совпавшем с концом отдыха.
  `screen/workoutExecution/WorkoutExecutionScreen.kt` (блок PrimaryButton).
  Идея: кнопка 0,6 с после смены «подход ↔ отдых» не принимает касаний.
- [x] **Пустое упражнение в редакторе.** Кнопка «Упражнение» сразу добавляет запись
  (`CreateWorkoutViewModel.kt`, AddExercise); открыть и закрыть лист — остаётся
  «Без названия, 0 кг», при выходе ложный «Выйти без сохранения?».
  Идея: при закрытии листа убирать упражнение без названия.
- [x] **«Отдых завершён!» поверх открытого приложения.** Канал IMPORTANCE_HIGH
  (`service/TimerNotificationService.kt`), всплывашка висит над шапкой экрана тренировки и
  дублирует звук/вибрацию самого приложения.
  Идея: не публиковать уведомление, когда приложение на экране.

## PR 2 — заметные недочёты интерфейса

- [x] **Строка музыки у главной кнопки.** Без запущенного плеера «Запустить музыку» по тапу
  сразу открывает Яндекс Музыку, а стоит в 10 dp над главной кнопкой. Иконка просьбы о доступе —
  колокольчик (NotificationsActive), строку нельзя скрыть. `components/music/MusicBar.kt`.
- [x] **Обводки почти не видны.** `outline` и `outlineVariant` — один цвет `#26262E` на фоне
  `#0B0B0F` (≈1,2:1): границы полей, дорожка прогресса. `ui/theme/Theme.kt`, `Color.kt`.
- [x] **Идущая тренировка не отмечена в очереди.** `runningWorkoutId` используется только в
  большой карточке и меню, строки очереди его не видят. Превью идущей тренировки не показывает
  сделанное по упражнениям.
- [x] **Плитки кг/повт не выглядят нажимаемыми.** У заметки есть карандаш, у плиток нет.
- [x] Мелочь: в диалоге выхода «Выйти» выглядит как «Отмена» — можно выделить цветом ошибки.
- [x] Мелочь: виджет без фирменного акцента. («Обрезанная» последняя строка — прокрутка списка, так задумано.)

## PR 3 — техника и доступность

- [x] ~~**Зоны нажатия меньше 48 dp**~~ — ложная находка: аудит мерил видимый размер.
  Compose сам расширяет зону касания до 48 dp: чип упражнения и строка веса на отдыхе — 48 dp
  по дампу uiautomator, ручку перетаскивания удалось потянуть в ~8 dp от иконки.
- [x] **Крупный шрифт (200%):** строка музыки — высота «не меньше 56 dp» вместо фиксированной,
  при 200% растёт в две строки. ~~«Новая» закрывает ⋮ последней строки~~ — ложная находка:
  у списка нижний отступ 96 dp, при докрутке последняя строка выходит из-под кнопки.
- [ ] **Перерисовка во время отдыха** — отложено осознанно: тормозов не видно, а исправление —
  перестройка экрана на 830 строк. `uiState` (тикает каждые 200 мс) читается в корне
  `WorkoutExecutionScreen`. Вернуться, если появятся подтормаживания.
- [x] **Predictive Back:** `BackHandler` на экране тренировки перехватывает «назад» только при
  записи завершения и когда под экраном пусто (`interceptsBack`); обычное сворачивание отдаётся
  навигации — работает анимация предпросмотра жеста.
- [x] ~~**TalkBack**~~ — не нужно: приложением пользуется только автор (решение 01.10.2026).
- [x] Контейнерные цвета темы заданы из палитры (оливковый тон акцента, тёмно-красный для ошибок).

## PR 4 — фича: прошлый раз на экране подхода (полный путь: спека → план)

- [ ] Экран подхода не показывает прошлую тренировку: «прошлый раз» есть только в превью.
  Вес на плитке и так последний (правка веса сохраняется в упражнение), но не видно повторов
  и разбивки по подходам — поэтому журнал ведётся в заметках («последний 31», «27.5 сделал…»).
- [x] Шаг колеса веса 0,25 кг (`WheelPicker.kt`, WeightValues): +2,5 кг — 10 шагов.
  Сделано: вес в кг — два барабана, целые кг и доли (,00/,25/,50/,75).
- [ ] Кнопки в постоянном уведомлении («Закончить подход» без разблокировки).

## Отброшено при проверке

- «Ещё не делали» на всех упражнениях — не баг: подпись строится по записанным подходам,
  а их пишут только с БД v8; на свежих данных заполнится.
- Нет `enableEdgeToEdge()` — на Android 15+ система и так рисует от края до края, проблем с
  отступами не видно.
- Автодетектор impeccable разбирает только веб-разметку; по Kotlin/Compose он ничего не дал,
  все находки — ручные.
